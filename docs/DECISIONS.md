# ODRAVETH — Журнал решений

Технические решения и их обоснования. Продуктовые решения принимает только пользователь; они фиксируются в [`PRODUCT_BASELINE.md`](PRODUCT_BASELINE.md), а здесь — запись об изменении.

Формат: **ID · статус · дата** — контекст, решение, последствия. Статусы: *принято* (техническое решение, можно пересмотреть отдельной задачей с новой записью), *утверждено пользователем* (продуктовое), *временно* (действует до отдельной задачи).

---

### D-001 · утверждено пользователем · 2026-10-05 — Движок и язык

Godot Engine **4.7.2 stable**, **GDScript**. C# не используется, 4.8 dev/beta не используется. `config/features` в `project.godot` — `"4.7"`. Скрипт проверок отказывается работать с другой версией.

### D-002 · принято · 2026-10-05 — Рендерер Compatibility

**Контекст:** 2D карточная игра, Android — платформа №1, важен охват устройств.
**Решение:** `gl_compatibility` (OpenGL ES 3.0) для десктопа и мобильных.
**Почему:** максимальная совместимость с Android-устройствами, включая те, где Vulkan отсутствует или работает нестабильно; возможностей 2D-рендеринга достаточно для UI карточной игры.
**Последствия:** часть продвинутых эффектов Forward+/Mobile недоступна. Переход на `mobile` — одна настройка, но требует проверки на устройствах.

### D-003 · утверждено пользователем / принято · 2026-10-05 — Экран и ориентация

- Утверждено: 1920×1080, stretch `canvas_items`, aspect `expand`, только альбомная ориентация.
- Принято: ориентация `sensor_landscape` (альбомная в обе стороны, без портретной) — телефон можно держать любой стороной.
- Принято: на десктопе окно 1280×720 (`window_*_override`) — только для удобства разработки, на Android не влияет.

### D-004 · принято · 2026-10-05 — Набор autoload

**Решение:** autoload только `EventBus`, `SceneRouter`, `AppState`, `CardDatabase`. `SaveManager` — обычный класс, экземпляром владеет `AppState`.
**Почему:** каждый autoload обязан быть глобальным (сигнальная шина; роутер, переживающий смену сцен; состояние приложения; неизменяемые справочные данные). `SaveManager` — ввод-вывод без связи с деревом сцен: как класс он тестируется с временным путём и не даёт произвольным скриптам писать сохранение в обход `AppState`.
**Последствия:** обоснование и запись здесь — обязательное условие для нового autoload.

### D-005 · принято · 2026-10-05 — Навигация через SceneRouter и параметры маршрутов

**Решение:** все переходы — через `SceneRouter` по id из `Routes`; данные между экранами — параметрами маршрута (`apply_route_params`), а не через глобальные синглтоны. История — стек `{route, params}`; режимы push / replace / reset.
**Почему:** требование ТЗ не хранить runtime-состояние матча в глобальных структурах; единая точка для истории и кнопки «Назад» Android; экраны не знают путей к сценам друг друга.

### D-006 · принято · 2026-10-05 — Формат сохранений

**Решение:** локальный JSON в `user://odraveth_save.json`, обязательное поле `save_version` (сейчас 1), атомарная запись (`*.tmp` + rename), пошаговые миграции `_migrate_from_vN`, защита от перезаписи сохранения более новой версии, копия повреждённого файла.
**Почему:** JSON читаем человеком и безопасен (в отличие от `str_to_var`/`bytes_to_var` с объектами); `save_version` — требование ТЗ; атомарность защищает от порчи при закрытии приложения Android во время записи.
**Последствия:** числа в JSON — `float`, код чтения приводит типы явно.

### D-007 · временно · 2026-10-05 — Формат данных карт

**Решение:** предварительно — JSON в `res://data/cards/`, файл `{"cards": [...]}`. Проверяются только утверждённые инварианты (раздел 8 ARCHITECTURE).
**Почему:** структура `data/` из ТЗ предполагает файлы данных; JSON удобно ревьюить в diff и валидировать.
**Последствия:** окончательная схема и типизированная модель карты подтверждаются в Stage 1; формат может измениться.

### D-008 · принято · 2026-10-05 — Строки интерфейса

**Решение:** русские строки пишутся прямо в сценах и скриптах; файлов перевода нет.
**Почему:** первая версия только на русском. Godot умеет извлекать строки из сцен/скриптов в POT, если локализация понадобится позже.
**Последствия:** идентификаторы и комментарии в коде — на английском, документация — на русском.

### D-009 · временно · 2026-10-05 — Маппинг кнопок главного меню

**Контекст:** ТЗ утверждает пункты меню, но не задаёт, на какой экран ведут «Играть» и «Колоды»; экранов «Прогресс» и «Настройки» нет в списке UI flow.

**Последствия:** финальный маппинг — открытый вопрос Q-14 в PRODUCT_BASELINE.

### D-010 · принято · 2026-10-05 — Системная кнопка «Назад» Android

**Решение:** `quit_on_go_back=false`; `SceneRouter` обрабатывает `NOTIFICATION_WM_GO_BACK_REQUEST` отложенно: есть история — назад, корневой экран — выход из приложения.
**Почему:** по умолчанию Godot закрывает приложение на любом экране. Отложенный вызов обязателен: смена сцены во время рассылки уведомления вызывает ошибку движка (найдено smoke-тестом).
**Последствия:** подтверждение выхода из идущего боя — задача экрана боя.

### D-011 · принято · 2026-10-05 — Тесты без сторонних фреймворков

**Решение:** собственный headless smoke-тест (`tests/smoke_test.tscn`) и `tests/run_tests.sh`; GUT/gdUnit4 не подключаются.
**Почему:** ТЗ запрещает сторонние зависимости без необходимости; для Stage 0 достаточно одной сцены-теста. Тест перехватывает ошибки движка через `Logger` (доступен в 4.7), поэтому скрытые ошибки не проходят незамеченными.
**Последствия:** при росте числа тестов (MatchEngine) можно вернуться к вопросу фреймворка отдельным решением.

### D-012 · принято · 2026-10-05 — Строгие предупреждения GDScript

**Решение:** 20 предупреждений, указывающих на вероятные дефекты (неиспользуемые переменные/константы, затенение, недостижимый код, вызов static через экземпляр, `int` как enum без приведения и др.), переведены в ошибки в `project.godot`.
**Почему:** в headless-режиме предупреждения GDScript не печатаются; как ошибки они видны при импорте и в smoke-тесте.
**Последствия:** стилистические предупреждения (выведение типов, `unsafe_*`, отброшенные возвращаемые значения) оставлены по умолчанию.

### D-013 · временно · 2026-10-05 — Placeholder UI

**Решение:** временная тема `assets/ui/placeholder_theme.tres` задаёт только размер шрифта 40; шрифт — встроенный в Godot (кириллица поддерживается, проверяется тестом). Фоновый цвет — стандартный цвет очистки Godot. Никаких изображений и скачанных ассетов.
**Почему:** ТЗ запрещает выбирать финальный шрифт и создавать финальный дизайн на Stage 0.

### D-014 · принято · 2026-10-05 — Зарезервированные каталоги

**Решение:** каталоги структуры из ТЗ, пока не содержащие файлов, хранятся с `.gitkeep`; назначение каждого описано в ARCHITECTURE §2. Пустых «декоративных» скриптов нет.

### D-015 · принято · 2026-10-05 — Значения, которых нет в ТЗ, не придумываются

**Решение:** реальные неоднозначности утверждённого ТЗ вынесены в «Открытые вопросы» PRODUCT_BASELINE и закрываются только решением пользователя; до этого в коде нет соответствующих констант и предположений.
**Примечание:** первая редакция этого решения ошибочно относила к неоднозначностям максимум существ на стороне поля (Q-01). Это было ошибкой Claude при составлении документа, а не пробелом в ТЗ — см. D-016.

### D-016 · исправление документации · 2026-10-06 — Максимум существ на стороне поля

**Контекст:** исходный утверждённый baseline Stage 0 уже содержал правило: максимум **7** существ на стороне поля каждого игрока. При первом составлении `PRODUCT_BASELINE.md` и `GameRules` значение было пропущено и ошибочно записано как открытый вопрос Q-01. Новое продуктовое правило не вводилось.
**Решение:** исправить пропуск в реализации и документации: **7** существ на стороне поля каждого игрока.
**Последствия:** PRODUCT_BASELINE §5 исправлен, Q-01 удалён из открытых вопросов; константа `GameRules.MAX_CREATURES_PER_SIDE = 7`, значение проверяется smoke-тестом. Поведение при попытке выставить восьмое существо — задача MatchEngine.
